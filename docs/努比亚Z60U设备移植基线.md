## 文档定位

本仓库是 Z60 Ultra 的独立设备仓库，目标是沿用 UniXNU-sheng 的组织方式，最终承载设备板级配置、XNU 内核配置、DarwinBoot 载荷、显示、UFS、触控和 GPU 适配。当前仓库只是从 UniXNU-sheng 建立的受控基线，不能把其中的 sheng 地址和驱动状态误认为 Z60U 已适配完成。

## 已确认的硬件事实

- 产品型号：NX721J，启动设备代号 PQ83A01。
- SoC 平台：实时设备树为 Qualcomm Pineapple；实机 qcom,msm-id 与 UEFI giulia.dts 完全一致，当前按 SM8650/Lanai 家族和 SOC_TYPE=2 适配。
- 内存和保留区：已从实时设备树和 UEFI giulia 内存库完成交叉比对，关键 UEFI、Kernel、Display 和 TZApps 区域一致。
- 存储：UFS 控制器基址 0x1d84000，PHY 为 Pineapple UFS PHY；这是后续 NativeUfs 的实机入口。
- 显示：DSI 面板 BF068_RM692H0，实测活动模式为 1116x2480，支持 60、90、120 Hz 命令模式。
- 触控：Goodix Berlin，节点兼容字符串 goodix,brl-d，挂在 QUPv3 GENI SE1 的 SPI 控制器上。
- GPU：Adreno Gen7.9.1，KGSL 节点基址 0x3d00000，芯片标识字节为 43 05 14 01，GMU 和 SMMU 节点均存在。

这些值来自 TWRP 下的实时设备树、sysfs 和分区只读采集。原始转储不进入 Git。

## 与 sheng 的边界

UniXNU-sheng 的 GPU 已经成功驱动，这是重要的代码和验证参考，但它的板级硬件是 SM8550/A740，不能直接复用以下内容：

- SM8550 的 KGSL、GMU、SMMU、时钟、电源和固件地址。
- sheng 的 NativeNovatekTouch 和 NT36532E 触控协议。
- sheng 的显示 DPU、面板和 framebuffer 参数。
- sheng 的 UEFI 包、DT 地址、CPU 频率表和 PMIC 寄存器。
- 任何以 sheng- 命名且在实现中写死地址的板级驱动。

可以复用的主要是结构、构建顺序、日志方法、GPU 驱动的抽象边界、DarwinBoot 载荷组织方式，以及已经验证过的 XNU/Metal 接口修补思路。Z60U GPU 适配应以 Pineapple 实时 DT 和 Linux KGSL 状态为输入，不能以 sheng 数值猜测。

## 移植阶段

### 第一阶段：UEFI 和启动载荷

先在独立 uefi-z60u 中完成 Lanai/SM8650 基线编译。使用 Binaries/giulia 的 SM8650 资源，SimpleFb 优先，不立即引入 Z60U 专用 DSI XML。验证目标是 UEFI 菜单、GOP、USB、UFS 枚举和 DarwinBoot 载荷入口。

### 第二阶段：XNU 最小启动

建立 nx721j 的 board 配置和 ADT 生成器，先只启用单核、PSCI、GIC、定时器、内存图和 framebuffer。首个 XNU 目标是能输出启动进度并停在可诊断状态，不同时启用触控、GPU 或写入 userdata。

### 第三阶段：只读 UFS 和系统根

依据实机 UFS 控制器和分区布局移植 NativeUfs，先以只读方式访问目标根文件系统。任何 userdata 写入都必须保持在用户确认范围内；原厂分区备份和 recovery、modem、persist 必须保留。

### 第四阶段：显示和输入

先复用 UEFI/ABL framebuffer 完成静态显示，再处理 DSI 电源和刷新。触控驱动不复用 Novatek，而是依据 Goodix Berlin 的 Linux 驱动、实时 DT 和固件文件名建立独立实现。输入初期可以使用虚拟按键验证用户空间启动链。

### 第五阶段：GPU 只读探测

先读取 GPU、GMU、SMMU 的状态和寄存器安全窗口，确认时钟、电源、固件、IOMMU stream 和中断。随后把 sheng 的 NativeAdreno 分成通用协议代码和板级常量两层，只有通用部分可以复用。Z60U 的 GPU 固件、芯片 ID、GMU 版本和 SMMU stream 必须从实机证据重新建立。

### 第六阶段：NativeAdreno 和 Metal

只有 GPU 只读探测、内存映射和 GMU 冷启动都通过后，才启用 NativeAdreno 的 ring、VM、提交、同步和 Metal 用户客户端。每一步都保持默认关闭，并使用独立启动参数，避免 GPU 失败阻塞 UFS 和显示诊断。

## 计划中的文件边界

- board.toml：最终改为 NX721J 的产品、SoC、UEFI 路径、userdata 和 ADT 参数；在实机分区布局完全核对前不写入猜测值。
- configs/nx721j_defconfig：从 sheng 配置拆出通用 XNU 选项，先关闭 sheng 专属触控、GPU、电源和频率功能。
- scripts/make-nx721j-adt.py：只使用实机 DT 证据生成 DarwinBoot/XNU 所需的 ADT，不复制 sheng 的 DT 地址。
- drivers/GoodixBerlinTouch：替代 NativeNovatekTouch，先完成协议和坐标报告，再接入 Apple HID 层。
- package/Nx721j*：存放板级电源、显示、UFS、GPU 探测和日志代码；每个硬件窗口都应有独立头文件和只读探测开关。
- uefi-z60u/Platforms/ZTE/nx721jPkg：固件平台包，不复制进本仓库的二进制子模块。

## 禁止事项

- 不把 sheng 的地址替换成 Z60U 地址后直接启动。
- 不把 DroidVM 的 VirtIO GPU 路径当成 Z60U 物理 GPU 驱动；DroidVM 的 GPU 由宿主机 KGSL 持有，和实机 NativeAdreno 不是同一条路径。
- 不在 UEFI 尚未通过前刷写 boot、vendor_boot 或 dtbo。
- 不执行 userdata 擦除、写入、GPT 修改或永久刷写，除非用户对具体破坏性步骤再次明确确认。
- 不把序列号、完整分区转储、Apple IPSW 和平台 seed 放进 Git。
